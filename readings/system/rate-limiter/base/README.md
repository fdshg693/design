# API レート制限

API サーバがリクエストを受ける直前に、その API キーの残り回数を判定する。超えていれば `429` と `Retry-After` を返し、アプリの処理には入らない。

## 前提

- 機能要件
    - API キーごとに上限がある(例: 無料は 60 回/分・バースト 10、有料は 600 回/分・バースト 50)
    - 上限内なら通し、超えたら `429` と待たせる秒数を返す
    - プラン変更は再デプロイなしで反映する(数十秒遅れは許容)
- 非機能要件
    - 判定が足す遅延は p99 5ms 以内
    - 判定機構が落ちても API 自体は止めない(短いあいだ上限を超えるのは許容)
    - 厳密に 1 回も超えないことまでは求めない
- 規模
    - 平均 2,000 req/秒、ピーク 10,000 req/秒
    - API キーは 50 万件。ピーク時に同時にアクティブなのは 5 万件と仮定
    - プラン変更は 1 日 1,000 件程度

## スコープ外

- API キーの発行・認証そのもの: キーはもう特定できている前提にするため
- 認証のない大量通信(DDoS)の緩和: キーを持つ正規クライアントの公平さが主題のため
- マルチリージョン: まずは単一リージョンで考える
