# 問題:ECカートシステムの設計(中級〜上級)

- 回答: `ANSWER.md`

## 背景

中規模のECサイト(登録会員 1,000万人、商品 SKU 500万点)で、カート機能をリニューアルする。
現状はRDBの1テーブルにカートを保存しており、セール時にDBが詰まりカート追加が失敗する問題が起きている。
また「カートに入れたのに決済時に在庫切れ」というクレームも多い。

## 要件

### 機能要件

- 未ログイン(ゲスト)でもカートに商品を追加できる。ログイン時にゲストカートと会員カートを**統合**する
- 会員カートは複数デバイス(PC/スマホアプリ)で同期される
- カートには「数量」「選択オプション(サイズ・色)」を保持し、表示時は**最新の価格・在庫状況**を表示する
- 価格がカート投入時から変わった場合、ユーザーに通知する(「値下がりしました」等)
- チェックアウト(注文確定)時に、在庫・価格・クーポンを確定させ、**在庫を二重に売らない**
- 会員カートは 90日間保持、ゲストカートは 7日間保持

### 非機能要件

- 平常時:カート操作 2,000 req/秒、ピーク(タイムセール開始直後):30,000 req/秒
- タイムセール対象の人気商品は在庫 1,000 個に対し、開始1分で 10万人がカート追加・購入を試みる
- カート表示の p99 レイテンシ 200ms 以内
- カートデータ自体の消失は許容しにくい(ただし数秒分の書き込みロスは許容可否を議論してよい)
- 注文確定は決済サービス(外部)を呼び出す。決済サービスは時々タイムアウトする

## 設問

1. **データモデルとストア選定**:カートデータをどこに、どんな構造で保存するか。RDB / KVS(Redis, DynamoDB等) / ドキュメントDB の選択理由と、ゲストカートの識別方法を述べよ
2. **カート統合**:ゲストカートと会員カートのマージ規則(同一商品が両方にある場合など)と、複数デバイスから同時更新された場合の競合解決を述べよ
3. **在庫引当のタイミング**:「カート投入時に在庫を確保する」「チェックアウト開始時に確保する」「決済完了時に確保する」それぞれのメリット・デメリットを比較し、あなたの方針を示せ。仮押さえする場合、期限切れの解放はどう実装するか
4. **価格と表示の整合性**:カートに保存すべき情報と、表示時に都度取得すべき情報を区別せよ。カート表示のたびに価格・在庫サービスを呼ぶとレイテンシが悪化する点をどう解決するか
5. **チェックアウトの一貫性**:在庫減算・クーポン消費・決済・注文作成を、決済タイムアウトを前提にどう整合させるか(分散トランザクション / Saga / 冪等キー等)
6. **タイムセール対策**:30,000 req/秒 かつ特定SKUにアクセスが集中する状況で、在庫カウンタのホットスポットとDB過負荷をどう避けるか。売り越しを防ぎつつ、ユーザー体験をどう保つか

## ヒント

- カートは「下書き」であり、注文は「確定した記録」。両者で求める一貫性レベルは同じか?
- ホットキー(人気SKUの在庫行)への書き込み集中は、シャーディングだけでは解決しないことがある
- 決済タイムアウトは「失敗」ではなく「結果不明」。後からどう確定させるか
- 在庫を仮押さえすると「買わない人が在庫を握り続ける」問題が起きる
