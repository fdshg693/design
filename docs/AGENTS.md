# 技術ドキュメント

特定の題材に紐づかない、技術そのものの解説を置く(例: Redis の概要、CAP 定理、OAuth 2.0 の流れ)
ユーザーは読んで学ぶ。分からないことは質問し、AI が回答を追記する
`projects/` や `quiz/` のような設計・出題はしない。設計・問題として深掘りしたくなったら、他フォルダでの題材化を提案する

## 他フォルダとの違い

| フォルダ | 主役 | ユーザーの役割 |
| --- | --- | --- |
| `docs/` | 技術・概念そのものの解説 | 読む・質問する |
| `readings/` | 完成済みのシステム設計 | 読む・質問する |
| `services/` | 特定サービスが活きる状況の問題 | 解く |
| `projects/` / `quiz/` | システム設計 | 設計する・解く |

- 各フォルダの `resource/` は、その題材のために質問された内容の調査結果。題材を問わず使える一般的な解説は `docs/` に書き、`resource/` からリンクする

## フォルダ構成

```
docs/
  <カテゴリ>/
    <技術名>/
      README.md       # 概要・目次・進捗
      <連番>-<名前>.md # 解説本体(1 テーマ 1 ファイル、例: 01-overview.md)
      QA.md           # 質問と回答のログ
```

- カテゴリ
    - `db`: データベース・キャッシュ・ストレージ(Redis、PostgreSQL、インデックスなど)
    - `messaging`: メッセージング・ストリーミング(Kafka、RabbitMQ など)
    - `network`: ネットワーク・プロトコル(HTTP/2、DNS、CDN など)
    - `distributed`: 分散システムの概念(CAP、合意アルゴリズム、一貫性モデルなど)
    - `security`: 認証認可・暗号(OAuth 2.0、TLS など)
    - `infra`: インフラ・運用(Kubernetes、監視など)
    - `front`: フロントエンド
    - 該当しない場合は必要に応じて追加する
- 技術名は英小文字のケバブケース(例: `redis`、`oauth2`)
- 小さな概念で 1 ファイルで足りる場合は、`<カテゴリ>/<技術名>.md` の単体ファイルでもよい(フロントマターは README と同じ)

## ファイル

- `README.md`
    - 先頭に以下のフロントマターを付ける
        - `summary`: 技術の概要(1文)
        - `category`: カテゴリ(カテゴリフォルダ名と一致させる)
        - `level`: 想定する前提知識のレベル(初級 / 中級 / 上級 など)
        - `status`: 進捗(未読 / 読解中 / 一通り完了)
    - 一言でいうと何か、何を解決するか、いつ使う/使わないか、読む順番(各ファイルへのリンク)を書く
- 解説ファイル(`<連番>-<名前>.md`)
    - 最初は `01-overview.md`(概要)から始め、必要に応じて追加する(例: `02-data-types.md`、`03-persistence.md`、`04-replication.md`)
    - 構成の目安: 概要 → 仕組み(図) → 主な使い方・ユースケース → 注意点・トレードオフ → 似た技術との比較 → 出典
    - 図は Mermaid。コマンドやコード例は短く
- `QA.md`: 質問と回答のログ
    - ユーザーが質問したら、AI が回答をここに追記する(見出しは `Q01` などの連番)
    - 解説本体の誤り・不足が見つかった場合は、解説ファイルも直してよい(設計と違い、比較のために残す必要はない)

## 進め方

- AI は解説者として振る舞う
    - 作成依頼があったら、まず `README.md` と `01-overview.md` を書く。それ以降のファイルはユーザーの興味に合わせて追加する(最初から全部書かない)
    - ユーザーの前提知識に合わせ、用語は初出で簡単に説明する
    - 回答の最後に、関連する次の質問やテーマを 1〜2 個提案してよい
- 仕様・数値・バージョン差は公式ドキュメントで確認し、出典(URL)を添える。バージョンで挙動が変わるものは前提を明記する
- 関連する `../projects/` / `../quiz/` / `../readings/` / `../services/` があればリンクする

- WEB 検索には `web-lookup` スキルがおすすめ
