# Web クローラ

与えられた URL からページを取得し、リンクを正規化して次の取得キューへ入れる。同じ URL の再取得は 7 日に 1 回まで。1 ドメインには 1 秒に 1 回までしか取りにいかない。

## 前提

- 機能要件
    - シード URL を起点にリンクを辿って HTML を保存する
    - URL は正規化してから同一判定する
    - 取得に成功した URL は 7 日後に再取得キューへ戻す
    - `robots.txt` で禁止されたパスは取得しない
    - 再取得を新規発見より優先しつつ、新規発見が止まらないようにする
- 非機能要件
    - 平均 50 ページ/秒を維持する
    - 1 つの遅いドメインや巨大なドメインが、他のドメインの取得を止めない
    - ワーカーが落ちても、キューに入れた URL は失わない(取得中の 1 件がもう一度走ることまでは許容)
- 規模
    - 50 ページ/秒 ≒ **430 万ページ/日**
    - HTML は圧縮後 30KB と仮定 → 50 × 30KB = 1.5MB/秒 ≒ **約 4TB/月**(最新版だけを残す)
    - 新規 URL が取得の 7 割と仮定 → 50 × 3,150 万秒/年 × 0.7 ≒ **約 11 億 URL/年**
    - 投入済み判定の Bloom filter は 1 URL あたり約 10 bit(偽陽性約 1% の目安) → 11 億 × 10 bit ≒ **1.4GB**
    - フロンティアに滞留する URL は 1,000 万件程度と仮定

## スコープ外

- JavaScript を実行しないと出ないリンク: 取得スループットの見積もりが変わるため
- 検索インデックスの構築: HTML を保存するところまでが主題のため
- ログインしないと読めないページ: 公開ページだけにするため
- マルチリージョン: まずは単一リージョンで考える
