# 02. 分析基盤のフォルダ単位アクセス制御

## 状況

全社の分析基盤として、階層型名前空間(HNS)を有効にしたストレージアカウント `contosolake` を使っている。ネットワークは 01 の要領で閉域化済みとし、ここでは **「誰が何をできるか」** だけを考える。

コンテナー `curated` のディレクトリ構成は次のとおり。

```text
curated/                (コンテナーのルート "/")
├── sales/
│   ├── 2026/
│   │   ├── 09/ ... 日次の parquet ファイル
│   │   └── 10/
│   └── master/
├── hr/
│   └── salary/         ... 給与データ(人事部以外は閲覧禁止)
└── finance/
```

登場人物(すべて Entra ID のセキュリティグループまたはマネージド ID)

| 主体 | やりたいこと |
| --- | --- |
| 取り込みパイプライン | 全ディレクトリへの書き込み(毎日新しいファイル・日付ディレクトリを作る) |
| 営業分析グループ | `sales/` 配下を読むだけ |
| 人事グループ | `hr/` 配下を読み書き |
| 監査担当者(個人) | 期間限定で `finance/` を読む |

最初の担当者は、次のように設定した。

1. 営業分析グループに、**ストレージアカウント** スコープで `Storage Blob Data Reader` を割り当てた
2. 取り込みパイプラインは、早く動かしたかったので **接続文字列(アカウントキー)** で接続している
3. 監査担当者には、ストレージアカウントの **アカウント SAS**(読み取り、有効期限 1 年)を発行してメールで送った

レビューで「営業分析グループが `hr/salary/` まで読める」と指摘された。そこで別の担当者が次のように直した。

4. 営業分析グループの RBAC を外し、代わりに `sales/` ディレクトリのアクセス ACL に、営業分析グループの `r--` を追加した

すると、次のことが起きた。

- 営業分析グループのメンバーが `sales/2026/09/` を一覧しようとすると **403**
- 慌てて `sales/` の ACL を `r-x` にし、さらに既定 ACL にも `r-x` を入れたところ、**10 月以降に新しく作られた日付ディレクトリは読める** が、**9 月のファイルは相変わらず読めない**
- パイプラインが作ったファイルの所有者を見ると、すべて `$superuser` になっている
- 「人事グループ以外は `hr/` に入れないように、ACL で拒否を書けばいいのでは」という意見が出たが、Data Lake の ACL には「拒否」の書き方が見当たらない。また、サブスクリプションの **共同作成者**(Contributor)を持つ運用担当者が、`hr/salary/` を読めるかどうかで議論になっている

## 問題

1. 設定 1 で、営業分析グループが `hr/salary/` まで読めてしまった理由を説明してください。RBAC のスコープを狭める(コンテナー単位にする)だけで、今回の要件を満たせますか?
2. 設定 4 の後、`sales/2026/09/` の一覧が 403 になった理由を説明してください。営業分析グループが `sales/` 配下を一覧・読み取りできるようにするには、**どのディレクトリ・ファイルに、どの ACL(アクセス ACL / 既定 ACL、`r` `w` `x`)** が必要ですか? ルート `/` も含めて答えてください
3. 既定 ACL を入れたのに 9 月のファイルが読めない理由と、対処を答えてください。今後、同じことを起こさないための運用上の工夫は何ですか?
4. 取り込みパイプラインがアカウントキーで接続していることの問題点を、ACL・所有者・監査の観点で挙げてください。どう変えますか? そのとき、パイプラインに与える権限は RBAC と ACL のどちらで、どの範囲にしますか?
5. 「ACL で人事グループ以外を拒否したい」「共同作成者は `hr/salary/` を読めるのか」について、RBAC と ACL が **どの順番で評価されるか** を踏まえて答えてください
    - ヒント: 管理操作のロールとデータ操作のロールは別物です。アカウントキーを取得できる権限との関係も考えてみてください
6. 監査担当者へのアカウント SAS の問題点を挙げ、代わりの方法を提案してください(SAS の種類と ACL の関係を含める)
7. 最終的な権限設計を、RBAC(誰に・どのスコープで・どのロール)と ACL(どのディレクトリに・誰に・何を)の表で示してください。ACL のエントリーに個人やマネージド ID を直接入れるか、グループを入れるかも決めてください
