# ECS タスク

## 一言でいうと

**「タスク定義(設計図)から起動された、1 個以上のコンテナのまとまり」**。ECS がスケジュール・起動・停止する最小単位で、Kubernetes の **Pod** に相当する。

- **タスク定義** = クラス(設計図)、**タスク** = インスタンス(実体)
- 「API サーバを 3 台」と言うとき、ECS では「API タスクを 3 つ」と数える

## 何を解決するか

- 「どのイメージを、CPU / メモリいくつで、どのポート・環境変数・権限で動かすか」を **JSON 1 つ(タスク定義)に固定**し、同じものを何個でも再現よく起動できる
- 一緒に動くべきコンテナ(アプリ + ログ転送のサイドカーなど)を **1 つの単位としてまとめて** 同じホストに配置し、ネットワークやボリュームを共有させる

## いつ使う / 使わない

| 使う | 使わない(別の選択肢) |
| --- | --- |
| 常駐する Web / API サーバ(→ サービスでタスク数を維持) | 数秒〜数分で終わるイベント駆動の小処理(→ Lambda) |
| 15 分を超えるバッチ・ジョブ(→ スタンドアロンタスク) | GPU を細かく制御したい・Kubernetes エコシステムが必須(→ EKS) |
| メモリに状態(キャッシュ、ID ブロックなど)を持つ常駐プロセス | タスクの停止で失われては困るデータの保存(→ DB / S3 に置く) |
